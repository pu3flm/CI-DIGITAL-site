Incident Record, IEEE-Record Terminology, Measured Evidence, and Complete Study Source

Author

Updated

August 1, 2026

Status: research-only; no control application or network configuration is deployed by this paper.

Evidence cutoff: 2026-08-01, America/Sao_Paulo.

Inference policy: technical inference is excluded by instruction.

Abstract

This paper preserves the recorded temporal-control incident from the phone–Nitro–RPi work, records terminology drawn from the cited primary publications and public IEEE standard records, reports the saved analytical and timing observations, and includes the complete study source code.

The incident record preserves the admissions, “I conflated devices and timestamps,” and, later, “I confused timestamps with control.” [12]

Kaul, Yates, and Gruteser define Age of Information as the current monitor time minus the timestamp of the most recently received update. [1, p. 1]

Maatouk, Kriouile, Assaad, and Ephremides define Age of Incorrect Information as a product of a time penalty and an information-error penalty. [2, eq. (3)]

Kao, Lam, Adelberg, Cheng, and Lee distinguish absolute temporal consistency from relative temporal consistency and give separate formulations for continuous and discrete objects. [3, Sec. 4.1]

IEEE 1588-2019 specifies Precision Time Protocol synchronization for clocks in packet-based networked systems. [7]

IEEE 802.1AS-2025 is the active IEEE standard record for timing transport over local area networks; its public description includes synchronized-time transport, timing-source selection, and indication of phase and frequency discontinuities. [8]

The saved Android/Termux timing sample contains four requested periods, 200 iterations per period, and observed miss counts of 0, 0, 49, and 200 for 10 ms, 1 ms, 100 µs, and 10 µs respectively. [16]

Those measurements are one finite user-space sample and are not presented as a worst-case execution-time bound, a schedulability proof, or a hard-real-time guarantee. [22]

Appendix A inventories twelve source files with SHA-256 digests and stated line counts; Appendices B–M contain their complete C, C++, Prolog, Tcl, and SQL listings.

Index Terms— Age of Information, Age of Incorrect Information, temporal consistency, networked control systems, Precision Time Protocol, IEEE 1588, IEEE 802.1AS, event-triggered control, scheduling observation, temporal validity.

I. Evidence Contract

A. Authorized claim classes

This paper uses five claim classes.

Mark Claim class Permitted basis
PUB Published fact Official IEEE record, published paper, or author-hosted manuscript
REC Recorded fact Edited incident record or saved project document
OBS Observation Saved measurement row or fresh command result with time and host
COMP Computed result Named equation, literal parameters, and reproducible solver output
GAP Evidence gap Explicitly unavailable, unmeasured, inaccessible, or undefined evidence

No claim class authorizes a causal conclusion.

No claim class authorizes extrapolation from a finite sample to future executions.

No claim class authorizes a local project rule to be described as an IEEE requirement.

No claim class authorizes a standard’s public summary to be represented as the full normative text.

B. Source hierarchy

Official IEEE Standards Association records are used for standard title, edition status, scope summary, publication status, and publicly exposed terminology. [7]–[11]

Author-hosted or institutional manuscripts are used for paper definitions, equations, theorem premises, and paper-stated limitations. [1]–[6]

The Obsidian engineering-stop note is used only as an edited record of the dialogue, project instructions, and project boundary. [12]

The local study files are used only for code facts, saved results, tool status, and test contracts. [13]–[22]

C. Explicit exclusions

This paper does not infer why the incorrect Wi-Fi statement was produced beyond the admission preserved in the incident record. [12]

This paper does not infer that Age of Information is an actuation-safety proof; source [1] presents it as a status-update timeliness metric.

This paper does not infer that Age of Incorrect Information is a general controller-safety proof; source [2] analyzes a slotted transmitter–receiver estimation model.

This paper does not infer that database temporal consistency is identical to network-interface state validity; source [3] defines consistency for real-time database objects and transactions.

This paper cites the public IEEE descriptions in [7] and [8] only for clock-synchronization and timing-transport scope.

This paper does not infer hard-real-time capability from Android/Termux observations. [16], [22]

This paper does not infer Nitro or RPi timing behavior because neither host contributes a saved timing sample to this study. [13], [22]

III. Primary Literature and IEEE Standard Records

A. Age of Information

Kaul, Yates, and Gruteser model a source that generates timestamped status messages, a communication system, and a monitor. [1, p. 1]

If the most recently received update at monitor time (t) carries timestamp (u(t)), the paper defines age as:

\[ \Delta(t)=t-u(t). \]

[1, p. 1]

The paper defines time-average age over ((0,T)) as:

\[ \Delta_T=\frac{1}{T}\int_0^T\Delta(t)\,dt. \]

[1, eq. (1)]

The paper states that timely updating is not the same objective as maximizing utilization or minimizing packet-delivery delay. [1, p. 1]

The paper describes queue backlog as one reason that transmitting updates as rapidly as possible can produce delayed status at a monitor. [1, p. 1]

The paper also states that reducing the update rate can leave the monitor with outdated information because updates are absent. [1, p. 1]

Those are statements about the paper’s status-update models; this paper does not extend them to an unstated controller model.

B. Age of Incorrect Information

Maatouk et al. define the conventional age penalty as:

\[ \Delta_{\mathrm{age}}(t)=t-U(t), \]

where (U(t)) is the timestamp of the last successfully received packet at the monitor. [2, eq. (1)]

They define an indicator error penalty as:

\[ \Delta_{\mathrm{err}}(t)=\mathbf{1}\{\hat X(t)\neq X(t)\}. \]

[2, eq. (2)]

They define the general Age of Incorrect Information metric as:

\[ \Delta_{\mathrm{AoII}}(t)=f(t)\,g\!\left(X(t),\hat X(t)\right). \]

[2, eq. (3)]

The paper describes (f(t)) as an increasing time penalty for remaining unaware of the correct status. [2, p. 4]

The paper describes (g(X(t),X(t))) as an information penalty reflecting the difference between the current estimate and the actual process state. [2, p. 4]

For the linear time penalty, it defines:

\[ f_{\mathrm{linear}}(t)=t-V(t), \]

where (V(t)) is the last instant at which the information penalty was zero. [2, eq. (7)]

For the paper’s selected indicator specialization, it gives:

\[ \Delta_{\mathrm{prop}}(t) = (t-V(t))\mathbf{1}\{\hat X(t)\neq X(t)\}. \]

[2, eq. (10)]

The analyzed system is slotted, with time normalized to slot duration. [2, Sec. III-A]

The source process in that model is an (N)-state discrete Markov chain, and the channel realization is modeled as independent and identically distributed Bernoulli behavior over slots. [2, Sec. III-A]

The paper assumes instantaneous ACK/NACK delivery in the model it analyzes. [2, Sec. III-A]

Those are model premises in [2], not local timing observations.

C. Absolute and relative temporal consistency

Kao et al. define temporal consistency for a real-time database as how well maintained data model the actual state of the environment. [3, Sec. 4.1]

They divide temporal consistency into absolute consistency and relative consistency. [3, Sec. 4.1]

For continuous objects, they describe absolute consistency through a maximum-age test against a predefined maximum age (T), also called an absolute validity interval. [3, Sec. 4.1.1]

For a relative-consistent set (R), the paper states:

\[ \forall X,Y\in R, \quad \left|\operatorname{timestamp}_X-\operatorname{timestamp}_Y\right| \le R_{\mathrm{rvi}}. \]

[3, Sec. 4.1.1]

The paper states that the maximum-age and relative-validity values for continuous objects are based on maximum rates of change and application-transaction correctness requirements. [3, Sec. 4.1.1]

For discrete objects, the paper states that update arrival is sporadic and that a suitable maximum age can be difficult to define because the object changes at an unpredictable rate. [3, Sec. 4.1.2]

For a discrete-object version (x), the paper defines the validity interval:

\[ VI(x)=[LTB(x),UTB(x)], \]

with the lower bound at the arrival of the update carrying that value and the upper bound at the arrival of the next update. [3, Definition 1]

The paper defines a current version (x_i) by the condition:

\[ t_c\in VI(x_i). \]

[3, Definition 2]

The paper defines absolute consistency for a discrete item as the availability of a current version at any instant. [3, Definition 3]

For a set (R) of discrete-item versions, the paper defines relative consistency by a nonempty validity-interval intersection:

\[ \bigcap_{x_i\in R}VI(x_i)\neq\varnothing. \]

[3, Definition 4]

The paper states that a relatively consistent database can remain stale; it gives the example of a database that never installs updates. [3, Sec. 4.2]

The paper distinguishes freshness at transaction read time in a weak absolute-consistent system from freshness at transaction commit time in an absolute-consistent system. [3, Definitions 6 and 7]

These definitions remain database and transaction definitions in this paper.

D. Event-triggered control and execution delay

Tabuada models a plant and feedback law as:

\[ \dot x=f(x,u), \qquad u=k(x), \]

and writes the measurement-error-perturbed closed loop as:

\[ \dot x=f(x,k(x+e)). \]

[4, eqs. (2.1)–(2.3)]

\[ \underline{\alpha}(|x|)\le V(x)\le\overline{\alpha}(|x|), \]

\[ \frac{\partial V}{\partial x}f(x,k(x+e)) \le -\alpha(|x|)+\gamma(|e|). \]

[4, Definition 2.1, eqs. (2.4)–(2.5)]

E. Networked control and maximum allowable transfer interval

Nešić and Teel analyze networked control systems with a maximum allowable transfer interval, abbreviated MATI, between transmissions. [5]

Their stated conclusion is semi-global practical input-to-state stability under the paper’s conditions and sufficiently small MATI. [5]

The author manuscript’s Lyapunov-UGAS protocol definition bounds a protocol Lyapunov function and requires contraction at transmissions. [5, Definition 1]

For each positive (,c), Theorem 1 requires (^*(,c)) and ({x,w,|e(t_0)|}c), then gives its stated practical error bound. [5, Theorem 1]

Theorem 2 adds its stated no-network ISS premise, retains a sufficiently small (), and gives practical state and network-error bounds under its hypotheses. [5, Theorem 2]

The author manuscript used in [5] describes its MATI conclusion as qualitative and calls for more quantitatively useful formulas that expose degradation as MATI increases.

This paper cites [5] only under its stated transfer-interval conditions.

F. Bounded uncertain time-varying delay

Cloosterman et al. present a discrete-time representation derived from the Jordan form of a continuous-time plant for a networked control system with uncertain time-varying delays. [6, p. 1575, Abstract]

Their abstract states that the represented delays may be smaller or larger than the sampling interval. [6, p. 1575, Abstract]

Their abstract states that the proposed linear-matrix-inequality conditions for stability and feedback stabilization are sufficient conditions. [6, p. 1575, Abstract]

The source record identifies the paper as an IEEE Transactions on Automatic Control technical note, vol. 54, no. 7, pp. 1575–1580, 2009. [6]

No necessary condition or unbounded-delay guarantee is attributed to [6] in this paper.

G. IEEE 1588 clock synchronization

The IEEE Standards Association record identifies IEEE 1588-2019 as active. [7]

The record describes a protocol for precise synchronization of clocks in packet-based networked systems. [7]

The record states that heterogeneous clocks may differ in inherent precision, resolution, and stability. [7]

The record states that profiles provide customization. [7]

The record identifies the protocol as Precision Time Protocol, or PTP. [7]

The record states that PTP supports synchronization to a grandmaster clock. [7]

The record states that corrections for path asymmetry are specified when asymmetry values are known. [7]

This paper cites the public description in [7], not the full standard clauses.

This paper therefore does not invent clause numbers or normative wording for unexposed definitions.

H. IEEE 802.1AS timing transport

The IEEE Standards Association record identifies IEEE 802.1AS-2025 as active and as superseding IEEE 802.1AS-2020. [8]

The public description states that the standard defines protocols, procedures, and managed objects for timing transport over local area networks. [8]

The public description includes synchronized-time transport. [8]

The public description includes timing-source selection, named “best timeTransmitter” in the 2025 record. [8]

The public description includes indication of the occurrence and magnitude of phase and frequency discontinuities. [8]

The IEEE 802 tutorial states that IEEE 802.1AS-2020 includes a profile of IEEE 1588-2019. [9, p. 60]

The tutorial describes mean link delay measurement through the IEEE 1588 peer-to-peer delay mechanism. [9, pp. 62–65]

The tutorial states that delay asymmetry must be measured outside PTP and may be included through managed objects. [9, pp. 62–65]

The tutorial describes offset calculation using receive timestamp, send timestamp, mean link delay, and a known asymmetry correction. [9, pp. 62–65]

In a node that supports multiple domains, the tutorial states that each domain is a separate PTP instance. [9, p. 73]

The tutorial states that the mean link delay for IEEE 802.3 transport depends on physical link characteristics. [9, p. 73]

The tutorial is informative material; it is not represented as the normative standard text.

#ifndef TEMPORAL_CONTROL_FRESHNESS_HPP
#define TEMPORAL_CONTROL_FRESHNESS_HPP

#include <algorithm>
#include <cmath>
#include <stdexcept>
#include <vector>

namespace temporal {

struct SnapshotResult {
    double oldest_age;
    double relative_skew;
    bool age_valid;
    bool skew_valid;
};

inline double age_at_effect(double sample_time, double effect_time)
{
    if (effect_time < sample_time) {
        throw std::invalid_argument("effect time precedes sample time");
    }

    return effect_time - sample_time;
}

inline SnapshotResult evaluate_snapshot(
    const std::vector<double>& sample_times,
    double effect_time,
    double maximum_age,
    double maximum_skew)
{
    if (sample_times.empty()) {
        throw std::invalid_argument("snapshot has no samples");
    }

    const auto bounds = std::minmax_element(
        sample_times.begin(), sample_times.end());
    const double oldest_age = age_at_effect(*bounds.first, effect_time);
    const double relative_skew = *bounds.second - *bounds.first;

    return {
        oldest_age,
        relative_skew,
        oldest_age <= maximum_age,
        relative_skew <= maximum_skew,
    };
}

inline double up_to_down_probability(
    double failure_rate,
    double recovery_rate,
    double horizon)
{
    if (failure_rate < 0.0 || recovery_rate < 0.0 || horizon < 0.0) {
        throw std::invalid_argument("rates and horizon must be nonnegative");
    }

    const double total_rate = failure_rate + recovery_rate;
    if (total_rate == 0.0) {
        throw std::invalid_argument("at least one transition rate is required");
    }

    return (failure_rate / total_rate)
        * (1.0 - std::exp(-total_rate * horizon));
}

}  // namespace temporal

#endif

static struct timespec add_nanoseconds(
    struct timespec timestamp,
    uint64_t nanoseconds)
{
    const uint64_t billion = 1000000000ULL;

    timestamp.tv_sec += (time_t)(nanoseconds / billion);
    timestamp.tv_nsec += (long)(nanoseconds % billion);
    if (timestamp.tv_nsec >= (long)billion) {
        timestamp.tv_sec += 1;
        timestamp.tv_nsec -= (long)billion;
    }

    return timestamp;
}

static int is_after(struct timespec left, struct timespec right)
{
    return left.tv_sec > right.tv_sec
        || (left.tv_sec == right.tv_sec && left.tv_nsec > right.tv_nsec);
}

static uint64_t nonnegative_difference_ns(
    struct timespec observation,
    struct timespec target)
{
    const uint64_t billion = 1000000000ULL;

    if (!is_after(observation, target)) {
        return 0;
    }

    return (uint64_t)(observation.tv_sec - target.tv_sec) * billion
        + (uint64_t)(observation.tv_nsec - target.tv_nsec);
}

static int parse_positive_u64(const char* text, uint64_t* value)
{
    char* end = NULL;
    unsigned long long parsed = 0;

    if (text == NULL || value == NULL || text[0] == '\0' || text[0] == '-') {
        return 0;
    }

    errno = 0;
    parsed = strtoull(text, &end, 10);
    if (errno == ERANGE || end == text || *end != '\0' || parsed == 0) {
        return 0;
    }

    *value = (uint64_t)parsed;
    return 1;
}

static int result_exit_code(uint64_t missed_deadlines)
{
    return missed_deadlines == 0 ? 0 : 1;

static int schedule_fits(uint64_t period_ns, uint64_t iterations)
{
    if (iterations == UINT64_MAX) {
        return 0;
    }

    return period_ns <= (uint64_t)INT64_MAX / (iterations + 1);
}

static void print_usage(const char* program)
{

int main(int argc, char** argv)
{
    uint64_t period_ns = 0;
    uint64_t iterations = 0;
    uint64_t missed_deadlines = 0;
    uint64_t maximum_release_lateness_ns = 0;
    uint64_t maximum_completion_tardiness_ns = 0;
    volatile uint64_t checksum = 1;
    struct timespec now;
    struct timespec release;

    if (argc != 3
        || !parse_positive_u64(argv[1], &period_ns)
        || !parse_positive_u64(argv[2], &iterations)
        || !schedule_fits(period_ns, iterations)) {
        print_usage(argv[0]);
        return 2;
    }

    if (clock_gettime(CLOCK_MONOTONIC, &now) != 0) {
        perror("clock_gettime");
        return 3;
    }
    release = add_nanoseconds(now, period_ns);

    for (uint64_t index = 0; index < iterations; ++index) {
        struct timespec start;
        struct timespec finish;
        const struct timespec deadline = add_nanoseconds(release, period_ns);
        uint64_t release_lateness_ns = 0;
        uint64_t completion_tardiness_ns = 0;
        int wait_error = 0;

        do {
            wait_error = clock_nanosleep(
                CLOCK_MONOTONIC,
                TIMER_ABSTIME,
                &release,
                NULL);
        } while (wait_error == EINTR);

        if (wait_error != 0) {

            perror("clock_gettime");
            return 3;

        if (clock_gettime(CLOCK_MONOTONIC, &finish) != 0) {
            perror("clock_gettime");
            return 3;

        completion_tardiness_ns = nonnegative_difference_ns(finish, deadline);

        if (completion_tardiness_ns > maximum_completion_tardiness_ns) {
            maximum_completion_tardiness_ns = completion_tardiness_ns;
        }

        release = add_nanoseconds(release, period_ns);
    }

    (void)checksum;
    printf(
        "iterations=%" PRIu64
        " missed=%" PRIu64
        " max_release_lateness_ns=%" PRIu64
        " max_completion_tardiness_ns=%" PRIu64 "\n",
        iterations,
        missed_deadlines,
        maximum_release_lateness_ns,
        maximum_completion_tardiness_ns);

    return result_exit_code(missed_deadlines);

#!/usr/bin/env tclsh

proc fail {label output {options {}}} {
    puts stderr "FAIL $label"
    if {$output ne ""} {
        puts stderr $output
    }
    if {$options ne "" && [dict exists $options -errorcode]} {
        puts stderr "error code: [dict get $options -errorcode]"
    }
    exit 1
}

proc run_checked {label command} {
    if {[catch {exec {*}$command 2>@1} output options]} {
        fail $label $output $options
    }
    if {$output ne ""} {
        puts $output
    }
}

proc run_measurement {probe period_ns iterations} {
    set command [list $probe $period_ns $iterations]
    set stdout_channel [file tempfile stdout_path]
    close $stdout_channel
    set stderr_channel [file tempfile stderr_path]
    close $stderr_channel

    set caught [catch {
        exec {*}$command >$stdout_path 2>$stderr_path
    } result options]

    set stdout_channel [open $stdout_path r]
    set output [read $stdout_channel]
    close $stdout_channel
    set stderr_channel [open $stderr_path r]
    set diagnostics [read $stderr_channel]
    close $stderr_channel
    file delete $stdout_path $stderr_path

    if {$caught} {
        if {![dict exists $options -errorcode]
            || [lindex [dict get $options -errorcode] 0] ne "CHILDSTATUS"
            || [lindex [dict get $options -errorcode] 2] != 1} {
            fail "timing measurement" "$output$diagnostics$result" $options
        }
    }
    if {$diagnostics ne ""} {
        fail "timing measurement diagnostics" $diagnostics
    }

    set metrics [string trim $output]
    set metrics_pattern {^iterations=[0-9]+ missed=[0-9]+ max_release_lateness_ns=[0-9]+ max_completion_tardiness_ns=[0-9]+$}
    if {![regexp $metrics_pattern $metrics]} {
        fail "timing measurement schema" $metrics
    }

    puts "MEASUREMENT period_ns=$period_ns $metrics"
}
