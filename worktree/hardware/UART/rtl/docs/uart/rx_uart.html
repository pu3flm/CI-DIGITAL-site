rx_uart

Author

Fernando Lessa Magalhães

Updated

September 14, 2026

Purpose

rx_uart receives a UART frame from rx and writes the recovered data to rx_out.

Ports

  • rx_clk
  • rx_start
  • rst
  • rx
  • length[3:0]
  • parity_type
  • parity_en
  • stop2
  • rx_out[7:0]
  • rx_done
  • rx_error

Internal Signals

  • parity
  • datard[7:0]
  • count
  • bit_count
  • state
  • next_state

States

  • idle
  • start_bit
  • recv_data
  • check_parity
  • check_first_stop
  • check_sec_stop
  • done

State Behavior

idle

  • rx_done = 0
  • rx_error = 0
  • if rx_start && !rx, transition to start_bit

start_bit

  • if count == 7 && rx, transition to idle
  • else if count == 15, transition to recv_data
  • else remain in start_bit

recv_data

  • if count == 7, sample rx into datard using {rx, datard[7:1]}
  • if count == 15 && bit_count == (length - 1), drive rx_out, compute parity, and transition to check_parity or check_first_stop

check_parity

  • if count == 7, compare rx with parity and update rx_error
  • if count == 15, transition to check_first_stop

check_first_stop

  • if count == 7, compare rx with 1'b1 and update rx_error
  • if count == 15, transition to check_sec_stop when stop2 is set, otherwise transition to done

check_sec_stop

  • if count == 7, compare rx with 1'b1 and update rx_error
  • if count == 15, transition to done

done

  • rx_done = 1
  • rx_error = 0
  • transition to idle

Counter Behavior

  • count tracks sub-bit timing and advances from 0 to 15
  • bit_count advances once per received data bit in recv_data
  • both counters clear in idle and done

Data-Length Handling

When the final data bit is reached, rx_out is selected from datard by length:

  • 5: datard[7:3]
  • 6: datard[7:2]
  • 7: datard[7:1]
  • 8: datard[7:0]

Observed Behavior

  • In the observed receive scenario with an 8-bit frame carrying 8'hA5, parity disabled, and one stop bit, rx_out became 8'hA5 and rx_done asserted at frame completion.
  • In the same scenario, rx_error remained 0.
