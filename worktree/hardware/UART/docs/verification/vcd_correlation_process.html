VCD Correlation Process

Author

Fernando Lessa Magalhães

Updated

September 14, 2026

Purpose

This process correlates a scoreboard failure line with the DUT/testbench waveform state at the same simulation time.

The objective is to answer, in a direct way:

  • what the test sent
  • what the scoreboard expected
  • what the DUT-visible path returned
  • what the selected waveform signals looked like at the failure timestamp

Inputs

Required files:

  • a saved simulation log with scoreboard output
  • a VCD file from the same run

Examples already present in the repository:

  • docs/verification/logs/xsim_uart_baud_boundary_test.log
  • docs/verification/waves/uart_baud_boundary_fail_code25.vcd

Rule Used

At a given timestamp, the effective waveform value of each signal is:

  • the most recent value change at or before that timestamp

This is the correct VCD interpretation.

Standalone C++ Utility

The submission includes a standalone utility kept next to the waveform evidence:

  • binary: docs/verification/waves/vcd_snapshot

It does not depend on task.

Help:

docs/verification/waves/vcd_snapshot --help

:D

Example: Baud Boundary Failure

The first failing boundary item is already known from the log:

  • baud code 25
  • expected byte 0x37
  • actual byte 0x9b
  • scoreboard timestamp 559615000

Run:

docs/verification/waves/vcd_snapshot \
  --log docs/verification/logs/xsim_uart_baud_boundary_test.log \
  --match-index 1 \
  --vcd docs/verification/waves/uart_baud_boundary_fail_code25.vcd \
  --preset baud-boundary

This prints:

  • the timestamp
  • expected byte
  • actual byte
  • the selected waveform signals at that same time

To save the output directly into a submission-side text file:

docs/verification/waves/vcd_snapshot \
  --log docs/verification/logs/xsim_uart_baud_boundary_test.log \
  --match-index 1 \
  --vcd docs/verification/waves/uart_baud_boundary_fail_code25.vcd \
  --preset baud-boundary \
  > docs/verification/waves/baud_boundary_snapshot.txt

Example: Parity Status Failure

Run:

docs/verification/waves/vcd_snapshot \
  --log docs/verification/logs/xsim_uart_parity_test.log \
  --match-index 1 \
  --vcd docs/verification/waves/uart_baud_boundary_fail_code25.vcd

For parity analysis, it is usually better to pass explicit signals or add a dedicated parity VCD if needed.

Built-In Presets

baud-boundary

This preset reports:

  • testbench.bfm_reg0.cfg_baud_rate_code[4:0]
  • testbench.bfm_uart0.send.data[7:0]
  • testbench.bfm_uart0.rxd
  • testbench.dut.clk_uart_rx
  • testbench.dut.rx_uart_inst.state
  • testbench.dut.rx_uart_inst.count[31:0]
  • testbench.dut.rx_uart_inst.rx_out[7:0]
  • testbench.dut.reg_bank_inst.reg2_data_rx[7:0]

Manual Signal Selection

If a custom set is needed, use repeated --signal arguments.

Example:

docs/verification/waves/vcd_snapshot \
  --timestamp 559615000 \
  --vcd docs/verification/waves/uart_baud_boundary_fail_code25.vcd \
  --signal testbench.bfm_reg0.cfg_baud_rate_code[4:0] \
  --signal testbench.bfm_uart0.send.data[7:0] \
  --signal testbench.dut.rx_uart_inst.rx_out[7:0] \
  --signal testbench.dut.reg_bank_inst.reg2_data_rx[7:0]

Output Use

Recommended usage in the document:

  1. quote the scoreboard failure line
  2. state the timestamp, expected byte, and actual byte
  3. paste the selected waveform snapshot values
  4. state the technical interpretation

Scientific Value

This process is useful because it replaces vague waveform commentary with a reproducible correlation between:

  • simulation log evidence
  • scoreboard expectation/result
  • VCD state at the same timestamp

That makes the analysis stronger and easier to justify. :D I HOPE!
