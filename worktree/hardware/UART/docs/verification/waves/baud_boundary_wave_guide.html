Baud Boundary Wave Guide

Author

Fernando Lessa Magalhães

Updated

September 14, 2026

Recommended Screenshot

The most significant waveform to append in the final submission is the first failing frame at baud code 25 from:

  • docs/verification/waves/uart_baud_boundary_fail_code25.vcd

Why this is the best figure:

  • it is the first failing boundary point after code 24 passes
  • it shows the configured baud boundary condition clearly
  • it shows the expected byte and the wrong DUT-observed byte in the same time window

Recommended Signal Groups

1. Boundary Setup

  • /testbench/bfm_reg0/cfg_baud_rate_code[4:0]
  • /testbench/dut/clock_div_inst/max_count[19:0]
  • /testbench/dut/clock_div_inst/max_count_rx_reg[19:0]
  • /testbench/dut/clk_uart_rx

Purpose:

  • show that the failing frame is being exercised at baud code 25
  • show the DUT RX timing divider values used for that boundary point

2. Serial RX Decode

  • /testbench/bfm_uart0/rxd
  • /testbench/dut/rx_uart_inst/state[2:0]
  • /testbench/dut/rx_uart_inst/count[31:0]
  • /testbench/dut/rx_uart_inst/bit_count[31:0]
  • /testbench/dut/rx_uart_inst/datard[7:0]

Purpose:

  • show the serial frame on rxd
  • show how the DUT RX state machine samples and assembles the byte

3. Expected vs Actual Byte

  • /testbench/bfm_uart0/send/data[7:0]
  • /testbench/dut/rx_uart_inst/rx_out[7:0]
  • /testbench/dut/reg_bank_inst/reg2_data_rx[7:0]

Purpose:

  • show the expected transmitted byte directly from the BFM task scope
  • show the DUT RX output and stored register byte
  • this is the clearest group for the final document because it exposes the mismatch directly

4. Status Context

  • /testbench/dut/rx_uart_inst/rx_done
  • /testbench/dut/rx_uart_inst/rx_error
  • /testbench/dut/reg_bank_inst/reg0_config[15:0]

Purpose:

  • show whether the DUT considers the frame complete
  • show whether an error flag is asserted during the failing high-baud case
