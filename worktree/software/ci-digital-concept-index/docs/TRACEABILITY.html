Source-to-Claim Chain

source_registry
 -> source_versions -> artifact_versions -> acquisition_activities
 -> extraction_runs/extracted_texts/spans -> derivation_runs
 -> segments -> evidence_items -> evidence_lineage_groups
 -> occurrences/measures/observation_edges + normalized memberships
 -> candidate + candidate observation links
 -> candidate_claim_links -> claims -> claim_evidence_links
 -> independence assessment/classes/claim link
 -> reviews -> claim_state_events
 -> semantic_assertions or mapping_registry

Every step retains exact IDs. The graph view is not the semantic claim view; it is reconstructed from immutable observation records.

Claim-to-Publication Chain

claim + exact sealed positive profile + typed evidence + current approved intended use + accepted review
 -> release_items(canonical record hashes) -> releases(non-recursive content artifact hash)
 -> verification_records
 -> validation_records(current use/user/context + sealed query/relevance FK)
 -> retrieval_evaluations(current sealed query/relevance FK)
 -> assurance_arguments and subclaims
 -> current-head release_approval_packages version + exact required release_baseline_snapshots
 -> approval_decisions(package ID) + approval_inputs
 -> publication_events(package hash + bootstrap/advance/rollback mode)
 -> current_published_releases / published_claims

Approval and successful publication are independently queryable. A failed event never appears in current_published_releases.

Change Impact Chain

change_request_items
 -> computed and declared dependency closure
 -> impact_items + closure hash
 -> stale claim events and reverify/revalidate obligation
 -> new V&V/review/release records
 -> deprecation or retirement decision
 -> tombstone

Historical source, evidence, claims, releases, and publication events remain resolvable throughout.
