Architectural Objective

The system owns a local append-only evidence and governance ledger. SQLite owns relational integrity and immutable transition guards; Python owns deterministic transformations, canonical serialization, path policy, and explicit command orchestration. Neither storage nor a graph view owns semantic truth.

Controlled Flow

source reference/bytes
  -> acquisition activity + source artifact/version + reviewed routing history
  -> extraction derivation + exact source/input/output/text/spans/quality
  -> segment derivation + provenance/language/scope
  -> normalization -> tokenization -> n-grams -> measures
  -> all-node observation graph
  -> explicit candidate nomination
  -> sealed non-vacuous profile -> term/concept + atomic scoped claim package
  -> independent semantic review
  -> immutable release-content candidate
  -> current verification + approved-use/query/relevance validation + retrieval + assurance
  -> immutable versioned approval-package head with complete frozen release-relative closure
  -> independent approval of that package
  -> bootstrap, advance, failed, or rollback publication event
  -> current-release derived view
  -> change/impact/reverification/revalidation/deprecation/retirement

Each arrow creates a new record and typed link. No command mutates an earlier observation into a candidate, candidate into a claim, claim into a decision, or decision into publication.

Four Mandatory Views

provenance_evidence_view

Unifies agents, source identities/routing/revisions, acquisition activities and tools, configuration applicability, derivation runs and normalized input/tool/output links, artifact identity state, extraction records/spans, segments/quoted-source links, evidence items, lineage groups, and lineage links. It is an audit view, not a semantic graph.

observation_graph

Unifies graph-node rows, token/n-gram occurrences, aggregate measures, co-occurrence, precedence, independent source-distribution similarity-signal records, and projected analytical edges. Nodes are selected independently of edges, preserving isolates. obs: predicates never enter semantic assertions.

reviewed_semantic_graph

Includes concept definitions, semantic assertions, and scoped mappings only when their exact claim is currently reviewed_accepted, its profile/ISF passes, and its domain firewall passes. A concept is not admitted merely because any unrelated accepted claim references it.

release_governance_view

Unifies intended uses, requirements, query sets/evaluations, reviews, verification, validation, assurance arguments, approvals, releases, publication attempts, changes, impacts, deprecations, and retirements.

Trust Boundaries

  • Source boundary: configured read roots; content remains inert data.
  • Write boundary: SQLite under var/ and deterministic files under exports/.
  • Semantic boundary: cid, ext, and ifc schemes remain independent; explicit scope, a cid predicate, or either cid endpoint activates the same claim firewall.
  • Governance boundary: executor, reviewer, approver, and publisher acts use distinct records and are checked for actor separation.
  • Publication boundary: the immutable release-content hash is never extended after V&V; publication binds the separate approved package hash, and only a valid bootstrap/advance or rollback event changes the derived current-release view.

Recovery

SQLite transactions own atomic local writes. A failed command rolls back its entire transaction. Existing immutable rows and previous successful publications remain intact. Recovery is rerunning a corrected command with a new record/run/event ID; it is never editing or deleting the failed historical record.
