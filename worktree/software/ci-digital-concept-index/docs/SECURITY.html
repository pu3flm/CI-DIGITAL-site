Threat Model

The local operator may ingest untrusted text, code, tool output, JSON metadata, or externally extracted document text. Primary risks are command/code execution, SQL injection, path escape, data leakage, provenance spoofing, semantic privilege escalation, identifier reuse, and release tampering.

Controls

No Active Content

  • The app has no network client, shell invocation, plugin loader, template evaluator, dynamic Python import, or model endpoint.
  • Source files are opened only as UTF-8 text.
  • PDF/OCR/parser execution is unsupported; externally produced text is inert imported data with provenance.
  • Ingested strings are never executed as SQL. Values use SQLite parameters.

Path Containment

  • Source paths must resolve under configured source_roots.
  • Database and export roots must resolve inside the app directory.
  • Export-relative paths cannot escape exports/.
  • Symlink resolution occurs before containment checks.

SQL Boundary

  • Dynamic table/view names are checked against SQLite inventory or fixed allowlists.
  • Identifiers pass a conservative ASCII identifier pattern before interpolation.
  • Record values are parameterized.
  • Foreign keys and recursive triggers are enabled on every connection.

Integrity and Nonrepudiation Limits

  • SHA-256 detects accidental/tampering changes but is not a digital signature.
  • Actor IDs and authority strings are registry assertions; this version has no authentication service.
  • External locators are not fetched or authenticated automatically.
  • authentication_status and completeness_status must therefore remain evidence-specific and may be partial/unavailable.

Semantic Privilege Separation

  • E-DOMAIN/E-PROJECT cannot be created by relabeling informative warrants or annotation/review/decision rows; typed authority/warrant FKs and triggers enforce their qualifying sources.
  • Claim type/version is bound to the exact recomputed seal of a non-vacuous positive profile, and one cid activation rule covers explicit scope, predicate namespace, and endpoints.
  • Reviewer differs from claim asserter; approval inputs differ from review/V&V executor; publisher differs from approver.
  • Observation predicates are prohibited in semantic assertions.
  • Projection membership cannot increase independent evidence.

Release Integrity

  • Release item canonical records/hashes and the non-recursive content artifact hash are recomputed independently of stored values.
  • Post-V&V approval packages freeze the exact required baseline closure in immutable snapshots; package hash, artifact identity/output, release-content link, and linear supersession head all recompute.
  • Approval targets an exact release/version/current package head and links explicit current V&V/retrieval/assurance inputs.
  • Successful publication checks the exact approved package hash, current gates, exclusive bootstrap/advance state, rollback preparation, and role separation.
  • Export requires the release to be current, validates its publication-bound package, emits both identities/frozen snapshots, and refuses overwrite of a non-empty destination.

Local Hardening

  • Keep source/migration/config files read-only for routine operators.
  • Restrict var/ and exports/ to the owning account.
  • Do not store secrets in source records, logs, JSON specs, SQLite, or exports.
  • Review rights/access notes before packaging evidence.
  • Treat copied databases/exports as sensitive research artifacts.
  • Verify executable/runtime paths independently; PYTHON launcher override is an operator-controlled trust boundary.

Known Limits

No OS sandbox, encrypted database, signatures, authenticated identities, access-control service, secret manager, malware scanner, parser sandbox, or remote audit service is included. A future network/UI deployment requires a new threat model, change request, verification, and intended-use validation.
